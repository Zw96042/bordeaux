The approved app-first Java command milestone is focused, bounded, and compatible with Bordeaux's existing native and LabVIEW export behavior.

Reviewed scope

This review covers the Java source scanner, Electron IPC boundary, shared command invocation model, marker inspector UX, compatibility behavior, tests, and smoke coverage added from the approved Java command integration plan. The milestone intentionally contains no robot runtime, annotation package, vendor dependency, PathPlanner adapter, Choreo adapter, Gradle execution, or Java class loading.

Assessment

No blocking findings. The implementation is suitable for real-project validation. It uses read-only, streamed and bounded source inspection; keeps filesystem paths and access in Electron's main process; preserves unresolved saved commands and the last successful catalog; and keeps new invocation metadata out of the LabVIEW binary contract.
  • Discovery: recognizes public command constructors and command-returning methods without executing Gradle or robot code. Streamed traversal plus directory, entry, depth, file-count, file-size, total-byte, type-count, command-count, schema-depth, object-field, and symlink ceilings bound untrusted input.
  • Custom data: recursively models primitives, enums, records, constructor-shaped objects, collections, string-key maps, optionals, and opaque JSON values. Java long/BigInteger/BigDecimal values remain exact strings, with signed 64-bit validation for long.
  • UX: persistent recent projects, searchable commands, stale last-known-good state, refresh/error notices, unresolved commands, explicit schema reconciliation, generated nested controls, late numeric validation, schema-aware JSON validation, associated labels, live status, large targets, and mobile-safe input sizing are present.
  • Compatibility: native planner output carries the additive invocation object. LabVIEW .bdx continues writing an empty command array, and a byte-equality regression test proves marker invocation data does not alter that binary.

Findings resolved during review

A command class that declared only a non-public constructor could be misclassified as having an implicit public no-argument constructor. Discovery now tracks declared constructors separately from the public constructors it can expose. Subsequent review also tightened source traversal so wide directories are streamed and rejected before an unbounded listing can be materialized, bounded Gradle settings reads, redacted filesystem paths at every IPC entry point, added exact large-number handling, validated custom JSON against discovered schemas, reconciled saved invocations after schema changes, exposed project scan status through a polite live region, and ensured every Java-specific control preserves the 44 px coarse-pointer target floor despite more-specific desktop sizing rules. Regression and smoke coverage exercise these cases.
