Bordeaux performance audit and repairs

Projectbordeaux
Versionv1
StatusAudit and 13 repairs completed · 2026-09-06

Thirteen verified performance problems repaired across renderer transport, playback, shared planning, field geometry, and Java discovery. Nine production files changed, with four regression suites and four reproducible benchmarks added.

The representative captured turn plans about 1.9× faster with all 675 samples, markers, and diagnostics exactly unchanged. The larger synthetic cases expose scaling failures that small projects hide. This is performance work, with no component, CSS, robot transport, or Java runtime edits by this audit.

Scope and reviewed state

Base commit: e2e3ea01ee097792e8aeda8aabf769b97057f493. The checkout already contained extensive uncommitted work and a concurrent UI audit. Only the nine performance file deltas listed below belong to this work; no commits were made. The final source hashes below identify the reviewed working files, including their preserved prior changes.

Independent passes examined planner math, derivative construction and reachability, preview/final worker transport, routine composition/playback, collision and portal analysis, Java discovery/catalog processing, worker lifecycle, export dispatch, project persistence, bookmarks/recent files, diagnostics, and agent bridge/session handling. App-level autosave debounce and planning orchestration were inspected. No additional measured bottleneck justified speculative pooling, persistent caches, network changes, or UI virtualization during this pass.
