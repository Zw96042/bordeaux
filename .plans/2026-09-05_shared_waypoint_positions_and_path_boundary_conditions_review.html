Shared waypoint positions and path boundary conditions

Implementation review for issue #166. Implemented and verified locally; no remaining blocking review findings.

Requested behavior

Shared waypoints reuse position only, as explicitly selected by the owner. Each path retains its own robot heading, tangent, and stop settings. Any waypoint may be reused, including an interior point. Initial swerve facing is independent of travel tangent. Paths expose scalar entry and exit speeds, vi and vf. Adding or switching a routine path must not briefly label a pending preview as skipped.

Implementation

  • Optional waypoint positionLink references preserve membership through file persistence and waypoint reordering. Connected legacy endpoint links also share position only.
  • A searchable Shared position control links the selected waypoint to another occurrence; Unlink makes it independent. Position moves translate local control handles without rotating them. Duplicating a path retains links; duplicating one offset waypoint detaches it.
  • Link undo restores waypoint/link state without restoring unrelated robot configuration or path settings. Typed coordinate edits use the same handle translation as dragging.
  • Existing planner support already honors feasible initial and final scalar speeds. The inspector makes those controls and endpoint stop overrides explicit; no planner algorithm rewrite was necessary.
  • Routine flow distinguishes preparing, unavailable, and genuinely unchosen branch previews.

Review

A separate read-only review identified two history hazards: finishing a draft before materializing the link input could lose the final edit, and whole-project undo snapshots could revert unrelated robot settings. Both were addressed before final verification. Review also caught legacy endpoint-link creation bypassing shared-position propagation and history ordering; it now uses the same waypoint history and propagates through the connected group. The final read-only review found no remaining blockers.

Editor refinement after owner feedback

Issue #167 refines the initial implementation. Shared-position targets are now explicitly opted in using Linkable and a short Point name; unnamed waypoints are excluded and repeated members of one named group are deduplicated. Hiding a point from the picker preserves existing links.

The start-facing arrow is now draggable even when tangent or look-at heading was active. Dragging or entering an initial angle changes only the first segment to manual facing and preserves the point and its tangent handles. Backward-facing offsets use the same convention across numeric, drag, and context actions.

Passive field notices occupy one compact row with consistent typography, a direct Optimize action when needed, and bounded expandable details. Normal trajectory rebuilding remains automatic. Library names and durations share an exact baseline. Entry/exit controls stay within the inspector.

The Robot workspace is now Settings, containing robot connection, units and existing configuration. Connection, units and JSON export no longer occupy the toolbar. Existing Save and underlying Java export workflows remain.

Issue #168: the initial simple restore check missed an outdated applied optimization in the actual saved project. Worker planning already generated a current normal trajectory, but library and routine consumers rejected that successful result solely because an old optimization artifact remained saved.

Outdated optimization inputs now use fresh normal planning consistently for library duration, routine preview and export. Valid applied optimizations remain selected. Invalid artifacts with matching current inputs still fail validation. Saved artifacts are retained so undo can restore their applicability; no optimization candidate is applied automatically.

Scope and limits

vi and vf are speeds along the path, not arbitrary field velocity vectors. Tank facing follows travel tangent. Existing acceleration, robot and trajectory limits still apply. Shared landmarks do not force every dependent path into a selective push; each modified path’s deployment status is invalidated by its changed coordinates. This work does not establish physical-robot execution behavior.
