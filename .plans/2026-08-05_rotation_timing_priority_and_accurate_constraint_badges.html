Add an explicit per-range timing priority so authors can preserve translational speed without violating angular limits, and make every range label describe the constraint that is actually tightened.

Context

Bordeaux currently treats authored heading as an exact function of path position. When heading changes faster than the active angular velocity or acceleration limits allow, the planner slows translation. That is correct for exact spatial heading tracking, but it is not always the desired tradeoff for a swerve robot.

Constraint ranges also copy the global limits when created. The field badge, outline, and segment inspector always print the copied velocity value, so an omega-only range misleadingly appears as ≤4.2 m/s.

Recommendation

Add optional rotationPriority: "heading" | "translation" metadata to constraint ranges. Omission means heading, preserving every existing project. The inspector calls this control Timing priority:

  • Heading adjusts translation so rotation stays on schedule.
  • Translation preserves translational timing while rotation catches up when needed.
Physical tradeoff: fixed translation timing, exact heading-at-position, and bounded angular motion cannot all be guaranteed for an impossible demand. Translation priority intentionally gives up exact spatial heading tracking rather than silently exceeding the robot limits.

The option is swerve-only. Tank paths continue following the path tangent. When ranges overlap, any active Heading-priority range wins, matching the existing conservative tightest-limit rule.

Range badges compare each local value with the global baseline, rank only genuinely tightened limits by normalized ratio, and show the strongest one. The stable tie order is velocity, acceleration, deceleration, angular velocity, then angular acceleration.

Implementation steps

  1. Extend the project type and validation with the optional priority enum, preserve it through normalized ranges, and document the compatibility invariant.
  2. Skip angular translation caps only where every active range requests Translation priority. Apply a shared fixed-timestamp, braking-aware angular follower after planner generation so profiled, optimized, LabVIEW Bezier, and LabVIEW clothoid outputs obey the same omega/alpha semantics without overshooting settled headings.
  3. Mirror the policy and follower in the canonical legacy renderer so preview, path checks, playback, and exported samples agree.
  4. Add the compact Timing priority segmented control to the constraint-range inspector with direct tradeoff copy.
  5. Add a shared label helper and use it on the field badge, outline row, and segment inspector. Do not draw a numeric badge when no local numeric limit is tighter than its baseline.
  6. Add regression coverage for defaults, validation, speed preservation, bounded continuous heading lag, no-overshoot catch-up, endpoint convergence, overlap behavior, tank rejection, and honest range labeling.
