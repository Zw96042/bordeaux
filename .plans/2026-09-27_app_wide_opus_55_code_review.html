Review the whole application, remove duplicated responsibilities, and repair confirmed recovery and trajectory-consistency defects.

Baseline: bee1655c050fb9e917d68ea4a728e513548fe23e. The original request was an app-wide Opus 5.5 review; subsequent steering explicitly authorized Opus to implement code cleanup. No commit, release, deployment or robot operation was requested or performed.

Method and scope

Six read-only review passes used the installed, authenticated Claude integration with exact model ID claude-opus-5-5: renderer, Electron/MCP, shared planning/export, tooling/release, and two coverage passes. The model identity was verified in each invocation's initialization metadata. The coordinator reproduced high-priority findings with real project functions, built renderer code, and isolated native Electron input. Reviewer source analysis is distinguished from executed evidence below.

Every one of the 165 tracked source/style/HTML files under src/ was inspected across the passes; callers were traced for reported findings. Read-tool coverage is an inventory, not proof that every possible execution path is correct. Scripts, CI, packaging and benchmark modules were reviewed; test and UI-harness bodies were sampled. Fonts and image assets were not audited. Untracked Java/example directories contained generated output, not additional application source.

The existing robot boundary remains a hard constraint: local saving does not connect to a robot, push stays explicit and scoped, and optimization candidates require explicit application. No hardware, live robot, native Windows/LabVIEW installation, packaged installer, or multi-platform release sign-off is claimed.

Implemented cleanup

Opus implemented four bounded cleanup areas plus a persistence follow-up; the coordinator integrated the changes, updated contributor-facing storage documentation, migrated a remaining branch test, corrected two new test fixtures, applied the independent reviewer’s two persistence corrections, and closed a pre-existing New-project Save As guard gap identified during re-review. Production source has a net reduction of 461 lines (449 added, 910 removed), including the two new shared owners. No dependency or release-workflow changes.

  • Removed three unused routine-preview modules and their live-app plumbing. Tests now exercise the current routine model and planning hook. Kept the still-live direct-preview worker path.
  • Consolidated numeric commits, shared command validation, accepted-or-normal trajectory selection, physical planner-input preparation at five call sites, sample constants, transient editor keys and benchmark statistics.
  • Kept routine planning inputs stable across Wait-only edits and carried authoritative event times into the timeline. Untouched Settings values preserve their exact stored units and optional emptiness.
  • Added provenance-aware legacy recovery and pre-mutation workspace conflict checks; consolidated linked-project freshness capture; batched local BDX generation and respected non-exportable paths; removed dead desktop locals and the unused update-failure wrapper.
  • Bound test discovery to maintained tests and excluded local scratch/work artifacts. The experimental benchmark verdict now rejects missing, skipped or failed producer correctness evidence.

App-wide review findings that need larger behavioral or architectural work remain explicitly listed below. The cleanup is not a claim that every pre-existing defect has been fixed.

Findings and disposition

P1 means potential data loss; P2 is a significant behavior or verification defect; P3 is narrower correctness or maintenance work. File locations below refer to the baseline reviewed and may move in the cleanup patch. “Remaining” means the issue was recorded but is not claimed fixed.

F01 · P1 · Legacy reopen can overwrite newer autosaved edits

Fixed: source-aware recovery and conflict protection · src/electron/projectOpening.ts:43, src/electron/main.ts:662

Runtime reproduction in an isolated temporary folder: workspace had Edited path; reopening Legacy.bordeaux.json returned Original path; the next autosave replaced the workspace with Original path. The workspace path can never equal the legacy file path in the existing recovery comparison.

Correction: The workspace records its imported source and original bytes; Recent switches to the workspace folder. A proven unchanged legacy source recovers the workspace. Unattributed older workspaces, unrelated sibling imports and externally changed sources cannot overwrite existing workspace files: Save/autosave refuse before mutation and direct the user to recover the folder or save the selected import elsewhere. Regression tests compare all preserved files byte for byte.

F02 · P2 · Binary export can discard an accepted optimization

Fixed and regression-tested · src/shared/export/robotBinary.ts:86, src/shared/planners/acceptedTrajectoryIdentity.ts:22

Runtime reproduction with a marker whose enabled argument has a catalog default: accepted and BDX-document duration 2.455913 s; binary duration 2.663521 s. Materializing defaults changes the optimization identity before trajectory selection, silently selecting ordinary planning.

Correction: Validate/select the accepted artifact against original authoring inputs; materialize command defaults only for emitted events. Compare actual samples and timing in a regression.

F03 · P2 · Agent analysis evaluates a different trajectory from the applied one

Fixed and regression-tested · src/shared/agent/pathAnalysis.ts:422

The same accepted fixture analyzed as 2.663521 s rather than 2.455913 s. Analysis also honors legacy plannerId by launching a fresh optimization that the user never applied.

Correction: Reuse the accepted-or-normal trajectory selection policy, including fail-closed handling for corrupt current artifacts.

F04 · P2 · Untouched Settings inputs change robot physics

Fixed; native keyboard verification passed · src/renderer/components/RobotPage.jsx:48

Native pointer/keyboard reproduction: focus Drive reduction, Tab, Save. A previously absent driveModel becomes a complete default physical model (54 kg, 2.6 N·m and other defaults), even though Use physical limits was never pressed.

Correction: Share numeric commit semantics with Num; preserve exact canonical values and make untouched drafts no-ops.

F05 · P2 · Routine-only edits restart all referenced path planning

Fixed; native Wait-only edit starts zero workers · src/renderer/app/App.jsx:313, src/renderer/app/App.jsx:1539

Native UI probe counted one new Worker after changing only a Wait from 1 to 2 seconds. Source tracing shows array-identity invalidation empties the run while planning and can clamp playback to zero. After cleanup the same native probe reports zero new workers and the new Wait value is retained.

Correction: Preserve the planning input array when its referenced path objects are unchanged. Verify no worker request for Wait-only edits, and still invalidate changed physical inputs.

F06 · P2 · Independent undo stacks violate chronological undo

Remaining · src/renderer/app/App.jsx:913, src/renderer/app/App.jsx:1511

Source-traced: a path edit followed by a configureRobot proposal leaves both histories. Undo prioritizes the older path entry; undoing the project snapshot can restore that already-undone edit. Routine history has the same interaction. Settings edits after a proposal are also swept into a whole-project undo. Not reproduced with native input in this pass.

Correction: Unify history ordering with typed entries and add application-level sequences covering proposals, path/routine edits and Settings. Avoid a broad history rewrite within the smaller cleanup patch.

F07 · P2 · Benchmark verdict accepts failed or skipped correctness evidence

Producer-gating defect fixed; broader provenance/coverage work remains · src/electron/benchmark/plannerBetaGate.ts:65

Direct runtime probe supplied planner.gates.passed=false and renderer correctness=null with fast samples. Verdict was accept and competitiveClaimsAllowed=true, with no blockers.

Correction: Require supported schema, successful producer gates and real renderer correctness evidence. Revision, corpus and completeness binding remain a separate prerequisite for credible comparative claims.

F08 · P2 · Save attempts BDX generation for deliberately non-exportable paths

Fixed; production Save/export verification passed · src/electron/main.ts:641, src/shared/export/robotBinary.ts:74

Source-traced: Save filters only waypoint count, then the binary builder rejects exportable:false. This aborts the entire generation batch, leaving prior BDX outputs while sources save and an error is surfaced. The all-or-nothing policy itself is not classified as a defect. After cleanup, a production main/preload/worker/writer check saves a two-path fixture with one non-exportable path and verifies exactly one BDX output with no export error.

Correction: Honor exportable:false, preserve atomic generation intent and accurate error messages; reuse bounded batch building.

Further maintainability work

These are follow-up opportunities, not automatic permission for a large rewrite. Prefer coherent changes with observable behavior tests.

  1. One history owner. Merge path, routine and project undo ordering before extracting more hooks from App. Move side effects out of React updater functions, and coalesce scrubs/name edits into user-level transactions.
  2. Retire obsolete pipelines. The dead routine-preview pipeline was removed in this patch and meaningful tests moved to the live path. Remaining legacy planner modes need caller tracing before removal. The legacy robot revision/pairing UI needs a separate boundary review: live SFTP transport types are shared with it and must survive.
  3. One owner per mathematical rule. Shared/renderer path math have real behavior differences, including draft motor acceleration and jiggle handling. Consolidation must preserve those differences deliberately. Range resolution, waypoint indexing, heading interpolation and angular-zone boundaries also need parity fixtures before merging implementations.
  4. Smaller orchestration seams. Extract real duplicated policies in project persistence, linked-command snapshots and agent proposals. Avoid moving the entire App or main process into a forest of forwarding hooks. Cache only on actual physical inputs; agent notes should not invalidate trajectory planning.
  5. UI style ownership. Remove confirmed unused class families, replace undefined tokens, and scope resets before considering cascade-layer or import-order changes. Any broader CSS change needs the complete affected-state screen matrix.
  6. Behavioral tests and harness reuse. Replace brittle source-string assertions and fake-hook loaders when touching the corresponding behavior. Reuse a common Electron harness launcher for timeout/error/output handling. Preserve failure artifacts in CI and make release startup checks explicit.
  7. Contract cleanup. A generatedTrajectory routine is supported by types/export but rejected by project validation; decide its supported product contract before enabling it. Saved accepted trajectories also need explicit waypoint-index shape validation. Do not revive retired velocity/translation-priority implementations solely because tests still exercise them.

Unconfirmed leads

Angular-zone overlap rules differ at boundaries across checking, solving and validation; this needs an isolated diagnostic regression before a semantic change. Opening a project without a valid activePathId may mark it dirty after effects settle. File creation uses hard links, whose behavior on removable FAT/exFAT storage was not tested. Long agent operations may hit a bridge timeout; no real deadline violation was measured. These are investigation leads, not demonstrated failures.
