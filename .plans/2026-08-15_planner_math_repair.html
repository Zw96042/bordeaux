Bordeaux Planner Math Repair

Projectbordeaux
Versionv1
Statusactive · 2026-08-15

Replace Bordeaux’s overlapping heading and timing calculations with one authoritative trajectory contract shared by planning, optimization, playback, validation, and export.

Context

Issue #142 tracks a release-blocking planner failure: ordinary paths can render a heading that disagrees with the selected heading law, switch timing behavior when priority placement changes, retain a coarse interactive result after a final solve, or reject valid geometry through a validator that models a different trajectory than playback.

The repair must preserve fixed geometry, authored endpoint velocities, stationary actions, constraint ranges, backwards traversal, marker timing, and the physical drivetrain envelope. A quieter error banner is not success; every downstream consumer must observe the same position, heading, velocity, acceleration, and time.

Recommendation

Define a single sampled trajectory as the authoritative planner output. Heading laws produce a desired heading field; timing priority resolves that field into a physically reachable actual heading during the solve; optimization changes timing only through the same constraint model; playback and export consume the accepted samples without re-deriving motion.

Acceptance rule. A result is publishable only when dense validation of the exact accepted samples reports zero violations and renderer playback matches those samples at every authored boundary and stationary action.

Implementation steps

  1. Capture the current saved project plus minimal fixtures for manual, tangent, targets, and look-at heading; heading/translation priority; before/split/after blending; nonzero endpoints; waits, turns, and jiggles.
  2. Write red-capable trajectory-contract tests that compare planner samples, final optimization, renderer pose-at-time, markers, and export-facing samples.
  3. Separate desired heading law from actual heading state and solve the actual state causally under angular and coupled swerve limits.
  4. Make the optimizer operate on that same state and replace global slowdown/fallback heuristics with validated local reachability constraints.
  5. Delete renderer-side reconstruction that can disagree with accepted samples; adapt only representation and stationary metadata.
  6. Run deterministic corpus and seeded property tests across modes, priorities, reversals, boundaries, and physical configurations.
  7. Complete independent review, full build verification, and an in-app replay of the user’s saved fixture before relaunch.

Risks & mitigations

RiskLikelihoodMitigation
Safety regression hidden by a permissive fallbackhighFail closed on the accepted sample stream and retain zero-violation dense validation.
Planner rewrite changes established path timingmediumFreeze representative corpus outputs and distinguish intended semantic corrections from regressions.
Sample-density-dependent decisionshighUse continuous/one-sided boundary math and verify identical semantics across 56, 112, and 224 samples per segment.
Preview/export divergencehighMake both consume authoritative accepted samples; test pose and marker equality.

Verification

  • A deterministic focused command reproduces the current saved-project failure before the repair and passes afterward.
  • Seeded property coverage reports zero constraint violations and no NaN/discontinuity across the supported heading and priority matrix.
  • npm test, npm run typecheck, npm run build, and git diff --check pass.
  • The relaunched app plays the saved fixture without fallback, stale geometry, heading jumps, or renderer/export disagreement.

Non-goals

  • Changing authored field geometry or silently relaxing robot constraints.
  • Preserving invalid timing merely because an older preview displayed it.
  • Adding more user-facing planner modes before the existing contract is reliable.
