The optimizer now has an explicit per-path workflow: draw normally, search inside a controlled corridor, compare, then apply a stable result.

UI revision after owner feedback

The owner found the first inspector too wordy, slow, and unintuitive. Functional correctness did not establish good product design. This revision replaces the instruction-heavy panel with the gain, clickable Normal/Optimized time rows, and a single Apply optimized action. In use identifies the saved selection separately from the preview highlight.

The toolbar Optimize action starts the quick search directly when a current result does not already exist. Reopening a candidate or applied result does not start another job. Closing either through the toolbar or inspector restores the saved selection. Search settings contains path freedom, deeper search, and Optimize all; diagnostics remain collapsed under Details. The inspector uses the existing theme and is 300 px wide.

Also fixed the corridor's Imperial input: its previous unit override incorrectly kept meters visible. Display and edits now convert correctly between feet and canonical meters. Equal-duration candidates are compared by actual samples, geometry, actions, and markers before treating them as already applied.

UI revision verification: 23 focused tests passed; type checking, renderer build/budget checks, and diff checks passed. The real Electron workflow passed 19 checks, preserving the 15 earlier behaviors and adding direct search, compact disclosures, and reopening checks. The harness now refuses to click controls hidden inside closed disclosures. A separate source and screenshot review found no blocking issues. Solver code was unchanged in this UI revision.

Review boundary

Reviewed the local, uncommitted optimizer implementation on main, based on e2e3ea01ee097792e8aeda8aabf769b97057f493. The repository already contained substantial planner, Java, and UI work; that work was preserved. This report describes the optimizer changes, not an audit or release of every dirty file.

The owner approved the existing UI/code as a base and permitted replacement where necessary. The implementation retains the fixed-geometry physics pipeline and existing editor components, adds a focused optimization inspector, and removes the project-wide mode switch from the authoring flow.

Implemented contract

  • Normal editing remains fast and receives authoritative physics timing after settling. Normal and optimized results use the same constraints.
  • Default search checks up to 24 candidates with a five-second target; deeper search checks up to 48 with a fifteen-second target. The corridor is adjustable from 0.03 to 1.5 m in the current display units.
  • Progress, candidate, and applied selection are separate. Completed jobs cannot apply themselves. Cancellation or deadline termination preserves the last independently validated checkpoint for comparison.
  • Apply stores exact trajectory samples, geometry, stationary actions, and markers with a versioned physical-input identity. Cosmetic changes preserve it; physical edits mark it stale. Playback, routines, reopen, and BDX export use the selected artifact without running a fresh search.
  • Optimize all searches sequentially and stages results individually. Existing selections remain selected. No-gain, unsupported, invalid, canceled, and budget-limited outcomes are distinguishable.

Independent review and fixes

A separate read-only source review checked ownership, serialization, stale handling, and physical validation. Findings fixed during that pass: cosmetic robot changes restarting selected planning, routine playback silently substituting normal for a stale artifact, and the normal comparison briefly displaying another path's old baseline.

Actual Electron verification also caught issues missed by source checks: the inspector could consume most of the field width, an internal-stop path had incompatible renderer/solver turn metadata, and the savings label briefly switched baselines during Apply. These were addressed before final verification. Missing authored action metadata remains an error.

Limits and follow-through

  • The owner's exact 3.7-second project was not supplied, so its historical idle transition was not traced directly. The replacement ownership lifecycle is tested using real workers, idle waiting, path changes, save/reload, and batch staging.
  • Search currently varies Bézier handle lengths while preserving directions. Mixed geometry, jiggle, or ambiguous portal cases may retain validated normal timing with an explicit unsupported-search explanation.
  • Each physics evaluation is synchronous. Five and fifteen seconds are search targets; a separate worker deadline provides a hard stop and uses the last delivered checkpoint.
  • Desktop feasibility and time savings do not establish robot tracking gains. No hardware runs were performed. Broader competition-route measurements remain useful before making marketing claims.
  • Code is verified locally and uncommitted. Lab issues #156–#160 retain implementation notes pending a closing commit; no release or deployment is implied.
