Create a cohesive launch system around Bordeaux’s wine-glass mark: three startup-motion directions, a complete static marketing site, reusable campaign media, and an edit-ready demo-video package.

Context

Bordeaux is a desktop FRC path, autonomous-routine, and Java-integration tool. Its existing product language is precise graphite UI with a cool blue technical accent; the existing application icon is a red-wine glass. The marketing direction should follow the hierarchy and restraint of learn.wilsonzach.com: near-black canvas, oversized editorial serif headlines, small monospaced labels, crisp white actions, minimal borders, and one characterful visual counterpoint.

Scope boundary. Startup ideas remain in an isolated prototype harness until the owner chooses one. The current application shell and its tests explicitly keep the dormant Chap loader out of production, so this work does not silently promote exploratory motion.

Recommendation

Use the wine glass as the constant and robot-path geometry as the system. Burgundy communicates Bordeaux; cool blue and telemetry details keep the identity rooted in engineering. Build the public-facing work as dependency-free static HTML, CSS, SVG, and JavaScript in top-level isolated directories so it neither disturbs the Electron renderer nor conflicts with the renderer migration already present upstream.

Implementation steps

  1. Build prototypes/startup-animations/ as a real frame-rendering pipeline and full-size review player: 1440×900 at 60 fps, MP4/WebM masters, exact-frame scrubbing, contact sheets, replay/rate controls, keyboard access, and reduced-motion behavior.
  2. Build marketing/ as a standalone static site with truthful product copy, responsive sections, download/source CTAs, feature explanations, FAQ, launch announcement, privacy note, sitemap, robots, manifest, structured data, and social metadata.
  3. Build launch/assets/ with source SVGs plus exported PNG variants for wordmarks, social cards, wallpapers, launch key art, product feature cards, press-kit inventory, and reusable video title cards.
  4. Create launch/video/ with a timed script, storyboard, voiceover, captions, shot list, recording checklist, edit notes, and a silent motion draft assembled from code-built product visuals and branded title cards. Keep real packaged-app capture as an explicit final-production replacement.
  5. Verify desktop and mobile rendering, keyboard and reduced-motion paths, static asset integrity, media dimensions, video playback, and the existing repository checks. Run an independent Codex review before handoff.

Verification

  • Serve the prototype and marketing directories locally; inspect at desktop and phone widths with the collaborative browser.
  • Exercise the picker mount/fallback path, replay and tuning source, CTA/menu behavior, video controls, keyboard focus, mobile inert navigation, and reduced-motion fallbacks.
  • Validate required SEO files and metadata, image dimensions, SVG parseability, video streams, and link targets with focused scripts.
  • Run npm run verify:renderer, npm run typecheck, and npm test to ensure isolated additions do not disturb the application.

Result

  • Replaced CSS choreography with three true frame-rendered startup films: Liquid Route, Impact Cut, and Waypoint Mark. Each ships as a 1440×900/60 fps MP4 and WebM plus poster, eight-frame contact sheet, manifest metadata, and reproducible source renderer.
  • Delivered a responsive dependency-free marketing site with complete launch copy, product visuals, an 18-second walkthrough, SEO/social metadata, structured data, captions, privacy, 404, robots, sitemap, manifest, and reduced-motion behavior.
  • Generated 42 deterministic SVG/PNG exports across logo, social, product, video, and wallpaper families, plus two clearly labeled ImageGen campaign assets.
  • Rendered a 37.5-second 1080p launch draft and supplied the voiceover, captions, storyboard, shot list, edit/audio brief, platform copy, press boilerplate, rights notes, and public-launch checklist.
  • Validation passed: 114 focused motion checks, 128 launch checks, renderer verification, TypeScript checks, and 197 existing tests. Desktop/mobile browser layouts, exact-frame scrubbing, video streams, representative frames, and collision mechanics were inspected; an independent motion review approved all three directions.
