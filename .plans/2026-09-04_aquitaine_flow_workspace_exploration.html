Recommended starting layout

Interaction ideas worth keeping

  • Automatic layout. A top-to-bottom sequence with clear decision lanes and rejoin points. Reorder steps and insert at connectors; no manual wire drawing or node positioning.
  • Compact node summaries. Show path or command name and the few values needed to read the routine. Detailed parameters belong in the selected-step inspector.
  • Fast insertion. One Add step entry and insertion controls between steps. Search Paths, Commands, Decisions and Wait from one chooser; show why unavailable actions need Java support.
  • Nested branches stay readable. Collapse a branch into a labeled summary and expand it in place. Keep preview branch selection visibly distinct from the condition evaluated on the real robot.
  • Context follows selection. Previewing a path highlights that step; editing its geometry opens Paths with an obvious Back to routine action. Return to the same step, scroll position and zoom.
  • Preview remains local. Label simulation and branch choices clearly. Push still reviews the explicit selected routine and dependencies; no robot execution chooser is introduced.

Smallest useful prototype

Start with the flow-first layout using the existing routine nodes and editing actions. Move collection management into the routine picker, allocate the center to the structured flow, and let Preview expand into the field view while preserving the same selection. First test a short sequence, a two-branch decision, nested decisions, and a long command name at laptop width. Decide whether a persistent field split is useful from those examples.

No graph library, freeform canvas, parallel execution model, or new routine semantics is justified by the space problem alone. Begin with the current vertical model, give branches room, and add zoom/pan only if representative routines need it.

Code grounding: src/renderer/app/App.jsx allocates the routine rail, field and inspector; src/renderer/components/RoutinePanel.jsx already owns insertion, reordering, collapse and preview highlighting. The proposed move can preserve those responsibilities and the existing push controller.
