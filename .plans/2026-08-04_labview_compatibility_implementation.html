LabVIEW Compatibility Implementation

Projectbordeaux
Versionv3
Statusdone · 2026-08-04

Add explicit LabVIEW-compatible trajectory modes and v4.4 interchange without changing the behavior of existing projects or removing the current handle-based planners.

Additive compatibility is the governing rule. Existing profiledSpline and optimizedTrajectory projects retain their planner IDs and behavior. New LabVIEW modes are opt-in, carry explicit compatibility settings, and continue to use the proven v4.4 binary boundary.

Implementation sequence

  1. Add dependency-free typed math modules with direct formula tests: degree-five Bernstein evaluation, shared join derivatives, signed curvature, 24-point quadrature, normalized Euler-spiral integration, reflection, extra arcs, and conservative overlap handling.
  2. Integrate labviewBezier and labviewClothoid planners behind the existing planner interface, including fixed-time samples and endpoint/constraint diagnostics.
  3. Persist and validate samplePeriodS, minTurnRadiusM, Bézier tangent interpretation, and the editable v4.4 file flags with backwards-compatible defaults.
  4. Make binary export derive Path Type from the explicit compatibility planner and sample period from the selected path. Add a strict v4.4 reader/import path, preserve modeled top-level values, and share hard resource limits.
  5. Expose the new choices in the canonical renderer and identify compatibility preview limitations honestly.
  6. Record invariants and unsupported command-array behavior in AGENTS.md, then run unit, type, build, Electron smoke, binary round-trip, and independent review checks.

Implemented result

  • Added opt-in labviewBezier and labviewClothoid planners while leaving both existing planners and the missing-plannerId fallback unchanged.
  • Added degree-five C² Bézier geometry, signed curvature, order-24 Gauss–Legendre arc length/inversion, and vertex-blend clothoids with reflected exits and extra constant-radius arcs beyond 90°.
  • Fixed-period timing now preserves exact interior stop ticks, leaves authored waits unscaled, applies reverse heading after every heading mode, and enforces local angular acceleration plus directional angular deceleration.
  • Added strict raw big-endian v4.4 reading, editable import with forced Save As, selected-path export, shared reader/writer bounds, and round trips for Reverse Path, Zero Velocity, Pickup Balls, Current Limit, Zero Translational Velocity, Correct at Beginning, and StoopidFast.
  • Added compatibility controls and a truthful approximate-preview disclosure to the canonical static renderer, plus durable maintenance invariants in AGENTS.md.

Real fixture validation

The user supplied 2CycleDepotPart1.bdx, a real rebuilt-LabVIEW v4.4 export (SHA-256 5ee07b8aa234f9ec19613245af25ee38fd9ff1b701f2e7b745b4d79dab7ee64f). It contains a straight clothoid trajectory and one serialized command.

  • The artifact directly confirms big-endian framing, the v4.4 field order, Linear 0 / Segment Type 0 for a straight clothoid, an empty terminal trajectory cluster, array-length no-deceleration sentinel, authored endpoint Conditions, and inverted screen-space velocity-vector Y.
  • The writer now follows those conventions. A command-free equivalent has the same 2,645-byte size and aligned structural boundaries.
  • The original remains intentionally rejected at its nonempty command record. Command payloads include LabVIEW Variant, type-descriptor, and Path data; this one fixture is not enough to define a safe generic parser.
  • Numeric trajectory bytes still differ because the LabVIEW file begins at a nonzero sampled velocity, extends beyond its updated endpoint, and reports 0.82 s for 43 samples at 20 ms. These are recorded as unresolved timing/integration behavior, not copied as fixture-specific constants.

Verification

  • 72 tests pass, including known-formula straight, left/right, 90°, >90°, adjacent-turn, exact start/interior/repeated-coordinate stop dwell, angular range/deceleration, low-limit preservation, unsupported-value rejection, oversized-array cases, and the real-fixture metadata conventions.
  • Binary writer → reader round trips consume EOF exactly, preserve units and editable flags, and keep imported files on Save As.
  • Legacy project fixtures still normalize to the original planner and defaults.
  • npm run typecheck, npm run build, and the real Electron smoke export/import pass.
  • Independent read-only review of schema, numerical edge cases, backwards behavior, and UI truthfulness.

Deliberate limits

  • Nonempty LabVIEW command arrays remain out of scope. The supplied artifact exposes a real command payload, but one serialized Variant/type graph and workstation Path does not establish safe record boundaries for every command.
  • Exact S-Curve2 floating-point parity remains unprovable without the missing LabVIEW Sigmoid.vi dependency and runtime fixtures.
  • Older BDX versions are rejected until their exact versioned payload typedefs are reconstructed; “backwards compatible” must not mean speculative parsing.
