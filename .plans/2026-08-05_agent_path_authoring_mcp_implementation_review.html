Final implementation review of Bordeaux's local MCP path-authoring surface. No blocking correctness or safety issues remain after the review fixes.

Scope

The review covered the private Electron-to-MCP bridge, live renderer session contract, proposal Apply/Reject flow, 2026 field vocabulary and geometry, planner-backed path analysis, route generation, focused repairs, project strategy terms, and Java semantic action binding. It judged the uncommitted implementation on branch main against the approved agent-path-authoring-through-an-mcp-server plan.

Result

Pass. The final independent Codex pass found no remaining blocking correctness or safety issues. MCP access remains disabled by default, no MCP tool can apply or persist a project change, and a proposal is not reported ready until the renderer acknowledges its preview.

Review findings resolved

  • Added session ID plus revision checks, renderer receipt acknowledgement, reload/close invalidation, and a single-ready-proposal invariant.
  • Made team vocabulary collisions with official terms ambiguous; rejected out-of-field raw and robot-relative coordinates instead of clamping intent.
  • Added footprint-aware HUB, field-boundary, alliance-barrier, TRENCH, and BUMP checks, including approach clipping, portal width, TRENCH height, and BUMP speed ranges.
  • Changed source attribution to monotonic waypoint-arrival mapping and activated waypoint-local limits from measured waypoint distances.
  • Required an authoritative, runtime-ready, uniquely tagged or project-bound Java action before authoring an endpoint event.
  • Made recommendation text report the actual bounded candidate set and exact time/clearance/curvature/rotation/waypoint tie-break.
