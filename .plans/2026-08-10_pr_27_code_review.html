Blocking findings

P1 Active drafts are outside dirty state, save/export, autosave, and close protection

App.jsx:551–560 updates only editStore during a drag. Dirty state changes only when project changes, and save/export serialize that committed project. From a clean document, starting a drag and invoking save or close before a terminal pointer event can save the old path or let Electron close without a warning.

Required: include the active draft in persistence snapshots and mark the transaction dirty on its first mutation. Cover save, export, autosave, new/open, and close.

P1 Undo during a drag corrupts history

App.jsx:549–603 pushes the pre-drag document immediately, but undo/redo still operate on committed state while the draft remains live. Reproduced sequence: hold a waypoint drag, press Cmd+Z, then release. The moved point returns on release, a second undo does nothing, and redo restores the old position.

Required: serialize all commands with the active transaction. Undo should cancel the draft; nudge, delete, save, open, and path switches must explicitly finish or cancel it.

P1 Preview provenance uses a path ID as if it were a revision

App.jsx:170–182 accepts a cached preview when preview.key === doc.id, although every edit of that path has the same ID and the scheduler already exposes preview.path. An old interactive curve can be paired with a newer waypoint list; FieldView.jsx:551–556 then builds editable segment hit paths from mismatched geometry and topology, so a fast follow-up insertion can target the wrong segment.

Required: require exact revision provenance and disable geometry hit actions whenever displayed geometry does not correspond to the editable document.

P1 The supposedly scoped update still escapes to the App root

FieldView.jsx:68–83 reports a fresh selected-position object on every draft revision. App.jsx:265 stores it in selPos, but that state is never read. This forces an App-root rerender at pointer cadence and undermines the central performance claim.

Required: remove the dead position pipeline or keep it in a ref/external store consumed only by the overlay that needs it.

P1 Continuous input can starve all curve updates until the pointer stops

path-preview.js:47–48 discards a completed result whenever any newer revision has been requested, while lines 131–137 continuously replace the queued job. If derive plus structured-clone time exceeds the input interval, every completion is stale by definition: waypoint nodes move but the curve freezes until motion pauses. A 100-waypoint interactive derivation measured 9.1 ms before copying an approximately 477 KB result, already longer than an 119 Hz input interval.

Required: allow monotonically newer completed previews to publish even when a replacement is queued, and benchmark the curve revision corresponding to the input rather than the next paint of any node.

Correctness issues to fix

StrictMode destroys the retained schedulers

The app is wrapped in StrictMode, but both schedulers are created in render with useMemo and permanently destroyed by effect cleanup at App.jsx:173–179 and 213–234. Development effect replay destroys the retained instance; subsequent requests no-op. Reproduced in Vite development: the waypoint moved but the centerline never updated. The production build updated correctly.

A runtime worker failure permanently stalls later previews

path-preview.js:84–116 keeps the failed worker after onerror and posts queued/future jobs back to it. postMessage errors and messageerror are unhandled. In a direct scheduler reproduction, the first failure produced error; retry changed the snapshot to pending with no path to completion.

Pointer release can commit a stale coordinate

usePointerDrag.js:40–44 flushes the last queued pointermove, then calls the end handler without applying the pointerup coordinates. The existing test uses the same coordinate for the final move and release, so it cannot detect this.

Switching paths cancels the draft but not the pointer session

App.jsx:566–569 cancels editStore when the path ID changes, but the global pointer controller is cleaned up only when FieldView unmounts. Switching paths preserves that component. A later pointer event can combine the new docRef with callbacks closed over the old active index and write the wrong path.

Geometry and interaction nits

Constraint ranges overdraw and over-hit their authored interval

field-scene.js:11–20 includes the sample before f0 and the sample at/after f1. That expanded span drives both the visible band and transparent click target. On a one-segment, 56-sample path, range [0.50, 0.51] renders and intercepts clicks across approximately [0.4821, 0.5179], while its handles remain at the exact bounds.

Short live ranges can disappear and then pop in larger on commit

FieldView.jsx:974–980 keeps only samples strictly inside the live interval. With 14 interactive samples, a valid [0.51, 0.53] drag contains no sample and draws nothing; on release the committed helper displays roughly [0.50, 0.5714]. Live and committed rendering should share an exact-boundary interpolating helper.

Performance and test nits

  • staticLayers still depends on the entire draft doc, so every pointer update rebuilds the complete SVG scene, labels, ranges, markers, and path strings. A lightweight moving overlay would better match the PR's architecture claim.
  • Two workers are eagerly created before editing. The exact production bundles grew by 36,585 raw bytes, and dense final results can approach 1.9 MB of structured-cloned object arrays. One lazy/shared scheduler and transferable typed arrays would reduce startup and copy cost.
  • The initial 14-sample fallback is exposed to time, graph, outline, inspector, and field consumers as if it were final while pending is returned but unused. Keep approximate geometry field-only or show metrics as pending.
  • The headline benchmark is not reproducible from the repository: there is no runner, fixture, trace, hardware/refresh-rate description, warmup policy, or run count. The tests replace the real Worker and strip module imports, so they cannot catch lifecycle, module-loading, structured-clone, or React provenance failures.

Copy-paste overall PR review

Requesting changes. The off-thread latest-job scheduler is a good direction and the existing checks pass, but the edit transaction and preview provenance are not safe yet. I can reproduce undo during a held drag being overwritten on release and corrupting redo history. Active drafts are also invisible to dirty/save/export/close state, so closing mid-drag can lose the visible edit without warning.
