Give agents a safe, typed way to understand the current Bordeaux project, translate 2026 REBUILT field language into geometry, generate and compare legal trajectory candidates, and stage the best candidate for review inside the app.

Outcome

A user should be able to tell an MCP-capable agent: “Start under our scoring-table-side TRENCH, go to the far edge of the NEUTRAL ZONE, come back to our shooting pose, and shoot using the fastest safe route.” The agent reads Bordeaux's field and robot context, resolves the named places, requests route candidates, and stages a proposal. It must also be able to inspect a pre-made or imported path, read its raw authored and sampled values, explain measured problems, and stage a focused repair. Bordeaux overlays every proposed change and its diagnostics on the field. The project changes only when the user clicks Apply in Bordeaux.

Optimization claim. “Best” means the fastest valid trajectory among the candidates Bordeaux generated under the selected robot, field, clearance, traversal, and action constraints. It is not a proof of a globally optimal autonomous routine. The UI and tool result must say which objective and candidate set were evaluated.

Recommended architecture

Ship one Bordeaux integration with two process roles:

  • Running desktop app: owns the live session, field data, route engine, planner calls, proposal store, and user approval UI.
  • Packaged --mcp-stdio mode: the MCP client launches the Bordeaux executable as a small stdio adapter. It authenticates to the running app over user-private OS IPC and translates MCP tools/resources into app-session requests.

This is preferable to an unauthenticated localhost port. Stdio is the normal local MCP integration model, while the private socket/named pipe keeps other websites and network peers away from the app. A direct Streamable HTTP endpoint can be reconsidered later if a target client cannot spawn a local process.

Connection and security contract

  • Add Agents → Enable MCP Access, disabled by default, with connection status and Copy MCP configuration. The copied command points to the installed Bordeaux executable with --mcp-stdio; it contains no secret.
  • The app creates a per-launch socket or named pipe plus a random nonce. The runtime descriptor lives under Electron userData with owner-only permissions. The adapter validates PID/start nonce and authenticates every connection.
  • No TCP listener in v1. The adapter returns a clear “Open Bordeaux and enable MCP access” error when the session is unavailable.
  • Bound every string, array, project snapshot, candidate count, sample count, request duration, and proposal lifetime. Cancel planner work when the MCP request is canceled or the app closes.
  • Annotate MCP tools accurately, but enforce read-only versus proposal versus commit behavior in code; annotations are not the security boundary.

This follows MCP guidance to prefer stdio for local servers or otherwise protect local endpoints with authorization/restricted IPC. See the MCP security best practices and the official TypeScript server guide.
