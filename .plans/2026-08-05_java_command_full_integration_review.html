Bordeaux now supports the complete annotated Java-command workflow: discover a GradleRIO project, install versioned support, generate a trustworthy command catalog, author typed trajectory events, export native trajectory JSON, and execute those events through a bounded WPILib runtime.

Context

This implements the approved Java command integration plan. The central constraint was to provide the LabVIEW VI-reference experience without loading arbitrary robot bytecode into the desktop app. The resulting boundary is generated JSON: source scanning is a helpful preview, while only annotation-processor output is authoritative and exportable.

Delivered system

AreaImplemented behavior
Desktop appLinks and remembers GradleRIO Java projects; previews managed support changes; installs or updates support; runs one fixed, explicitly trusted Gradle catalog task; exposes cancellation and bounded failure states.
Command UISearches generated commands, shows descriptions and parameter metadata, applies defaults, recursively validates structured values and exact numbers, reconciles changed schemas, and supports per-event cancel-at-path-end.
Annotations@BordeauxCommand and @BordeauxParam define stable IDs, labels, descriptions, units, defaults, and ranges. The aggregating processor validates factory signatures and emits a catalog plus compiled bindings.
Trajectory contractbordeaux-trajectory/1.0 exports all planned paths, samples, and stable command events. Catalog ID, support version, and canonical command hash bind an export to the exact generated robot registry.
Robot runtimeA strict bounded reader validates the native JSON, generated bindings construct commands from typed arguments, and the event runner catches up missed ticks, schedules each event once, and only cancels opted-in commands at path end.
PackagingThe application build produces and bundles bordeaux-runtime.jar and bordeaux-processor.jar. Installation writes only the reviewed managed block and .bordeaux support files; deployment remains GradleRIO-owned.

Review findings resolved

An independent read-only review focused on boundary safety and cross-language compatibility. The implementation was tightened before verification.

FindingResolution
Runtime coercionArguments are recursively validated before Jackson conversion, preventing permissive scalar or container coercion.
Exact numeric denial of serviceExact integers and decimals stay strings and share 1,024-character and exponent-magnitude limits in TypeScript, the processor, and runtime.
Collection ceiling mismatchShared export and renderer validation now reject arrays over 1,024 items and maps over 256 entries, matching the robot runtime before a file can be exported.
Unsupported optionals and defaultsNested optionals fail compilation; annotation defaults must satisfy the emitted schema and authored range.
Catalog identityA stable catalog ID and deterministic semantic hash are emitted, compiled, exported, and checked before any event is scheduled.
Support integrityThe install manifest records artifact and script hashes; inspection compares both installed and bundled artifacts and requires a compatible version.
Disconnected managed blockSupport readiness requires the complete dialect-specific Gradle block, including the apply line and both markers; marker-only tampering is covered for Groovy and Kotlin.
Untrusted Gradle executionOnly fixed arguments are allowed after an explicit prompt, output and duration are bounded, concurrent builds are rejected, and TERM escalates to KILL.
Platform command quotingThe Windows wrapper path is validated against command-shell metacharacters before execution.
Real integration coverageA temporary Gradle project runs the actual installed processor and feeds its generated catalog through the TypeScript parser and hash verification.
Annotation roundsThe processor aggregates through every round, with a second processor regression test that generates a command in a later round.
