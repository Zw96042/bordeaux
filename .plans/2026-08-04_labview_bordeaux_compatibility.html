Rebuilt LabVIEW Bordeaux writes a single path as raw, big-endian LabVIEW 4.4 flattened data; this checkout now emits that container, but its curve generation remains intentionally distinct and must not yet be called numerically identical.

Verdict: container-compatible, planner parity incomplete. The previous .bdx output was JSON and could not be read as a LabVIEW Bordeaux path. The new writer matches the proven v4.4 field layout, primitive encodings, units, and fixed 20 ms sample cadence, with an empty command list as requested. Exact clothoid, Bézier, and velocity-profile parity requires a dedicated compatibility planner and golden files generated by the rebuilt LabVIEW VIs.

The audit extracted front-panel typedefs, block-diagram resources, constants, and wires from the binary VI/CTL files and cross-checked the embedded papers and full Git history. The v4.4 binary contract

A .bdx file is not JSON, ZIP, an RSRC container, or a tagged message. It is a raw concatenation of flattened LabVIEW values. All numeric fields are big-endian/network order. Strings and one-dimensional arrays begin with a big-endian U32 byte/element count. Clusters are concatenated in typedef order with no alignment padding. Booleans are one byte. The first seven bytes of every v4.4 file are:

00 00 00 03 34 2e 34
└─ U32: 3 ─┘ └ "4.4" ┘
#Top-level valueFlattened contents
1VersionString 4.4
2DirectionRobot Backwards bool; Reverse Path bool
3Trajectory DataU32-counted trajectory-segment array
4Sorted commandsU32-counted command array; emitted as zero length
5Conditionssample period; linear limits; endpoint velocities; overrides; angular limits
6Updated WaypointsU32-counted {x,y,th} DBL clusters
7SummaryTime seconds DBL; Distance feet DBL
8Zero VelocityBoolean
9Path metadataDrive Type U16; Path Type U16
10–13Recent flagsPickup Balls bool; Current Limit DBL; Zero Translational Velocity bool; Correct at Beginning bool

Trajectory segment

String Segment Name
U16    Segment Type      // 0 Accel Straight, 1 Const Straight, 2 Blend,
                         // 3 Circle, 4 Bezier
Array   { DBL x, DBL y, DBL th }
Array   { DBL V, DBL Omega, { DBL vectorY, DBL vectorX } }
I32     Accel Index
I32     Decel Index

The velocity-vector order really is y then x in the LabVIEW typedef. Drive Type is 0 Nonholonomic or 1 Holonomic; Path Type is 0 Clothoid or 1 Bezier.

DBL Sample Period (s)
{ DBL Velocity fps, DBL Accel fps², DBL Jerk fps³, DBL StoopidFast fps }

        DBL Velocity Override, DBL Angle Override }
{ DBL Angular Velocity deg/s, DBL Angular Accel deg/s²,
  DBL Angular Jerk deg/s³ }

The new writer emits one selected path, converts SI values at this boundary, samples at 0.02 s, writes no commands or overrides, and atomically replaces the destination. When the current planner duration is not an exact 20 ms multiple, it stretches the complete time mapping by less than one tick and scales velocity and omega with it, so the final waypoint and kinematics remain aligned to the declared fixed-time grid. Stored endpoint-velocity conditions come from the actual first and last emitted samples, including planner clamping and stops. This is intentionally a small schema-specific encoder rather than a generic LabVIEW serializer.

Bézier math

The reference uses degree-five Bézier segments, not the degree-three curve currently in pm.ts:

Q(u) = Σ[j=0..5] C(5,j) (1-u)^(5-j) u^j Pj

P0 = Wi                         P5 = Wi+1
P1 = Wi   + Ti/5                P4 = Wi+1 - Ti+1/5
P2 = Ai/20   + 2P1 - Wi         P3 = Ai+1/20 + 2P4 - Wi+1

Ti is the waypoint tangent. Interior tangent direction comes from the signed perpendicular of the bisector of normalized neighbor directions; its magnitude uses the nearer adjacent distance and the turn-rate/elongation input. The Ai second-derivative values are shared across joins and weighted from provisional adjacent cubic segments, giving C² continuity and therefore continuous curvature.

Explicit handles can preserve this editor’s UX, but strict compatibility requires interpreting them as tangents: an outgoing quintic handle implies Ti = 5(Ci,1 − Wi), while an incoming handle implies Ti = 5(Wi − Ci−1,4). An interior LabVIEW-compatible join needs one shared tangent and one shared second derivative; arbitrary independent handles cannot retain both the current shape and LabVIEW C² behavior.

Derivative control points use the standard hodograph Dj = n(Pj+1 − Pj). Signed curvature is:

κ(u) = (x′y″ − y′x″) / (x′² + y′²)^(3/2)

LabVIEW evaluates the curve through a Bernstein–Fourier transform, which is mathematically equivalent to direct Bernstein evaluation but may differ at the last floating-point bits. Arc length uses 24-point Legendre–Gauss quadrature:

L(a,b) ≈ (b-a)/2 · Σ[i=1..24] wi · |Q′((b-a)xi/2 + (a+b)/2)|

The distance-domain jerk profile is then inverted back to Bézier parameter, with Chebyshev fitting/evaluation smoothing that mapping before positions are emitted at fixed time intervals.

Clothoid math

LabVIEW’s clothoid does not solve a spiral between two authored endpoint poses. It trims a polyline around each interior waypoint and inserts a symmetric, zero-curvature-to-maximum-curvature-to-zero-curvature blend. The normalized entry spiral uses parameter τ and a hard numerical step of 0.001:

θ(τ) = τ²
x(τ) = ∫[0..τ] cos(q²) dq
y(τ) = ∫[0..τ] sin(q²) dq

With physical scaling σ, s = στ and κ(s) = 2s/σ². For corner angle α and requested minimum radius R:

τmax = sqrt(|α| / 2)
σ    = 2 R τmax
Lhalf = σ τmax = R |α|
R(τ) = σ / (2τ)

The VI computes one half, reflects it for the exit, rotates/translates the blend into field coordinates, and trims both incident lines by the tangent-intersection distance:

dvertex = xσ − yσ / tan(τmax²)

Turns beyond 90° are separated into a capped spiral contribution plus an extra circular arc. Consecutive corners run through explicit overlap review and smoothing logic. This architecture explains why merely swapping a Fresnel integral into the current endpoint-pose solver would still not match Bordeaux.

Velocity and heading profiles

For Béziers, LabVIEW computes geometry and quadrature length, solves a jerk-limited S-curve in time, maps traveled distance back to curve parameter, and finally evaluates position/heading at the configured sample period. S-Curve2.vi uses paired sigmoid acceleration transitions and Newton iterations to solve time or peak velocity so the integrated distance reaches the goal. The older reference S-curve has the familiar seven jerk/constant-acceleration/constant-speed/mirrored-deceleration phases.

Clothoids are profiled segment-by-segment, including straight acceleration pieces and resampled blends. Turn radius is tied to centripetal acceleration by R = v²/ac, and adjacent short/overlapping turns can force repeated reductions.

Holonomic heading is independently time-profiled under angular velocity and acceleration constraints; it is not the current smoothstep interpolation over normalized path length. The current optimized planner’s 0.22/0.56/0.22 velocity smoothing also has no LabVIEW equivalent.

Implemented in this pass

  • Added src/shared/export/labviewBdx.ts with a big-endian, schema-specific LabVIEW 4.4 encoder.
  • Changed native .bdx export from JSON text to binary bytes and selected-path semantics.
  • Converted meters/meters-per-second/radians to feet/fps/degrees only at serialization.
  • Resampled the existing trajectory at a fixed 20 ms cadence and emitted LabVIEW position/velocity clusters, summary values, limits, enums, and current 4.4 flags.
  • Planned only the selected path, so a separate invalid path cannot block the single-path export.
  • Rejected line, arc, and mixed segment sets instead of silently mislabeling them as a whole-path LabVIEW Bézier; homogeneous Bézier and clothoid paths receive the matching enum/type.
  • Kept commands and per-waypoint overrides empty, matching the stated scope and avoiding unproven LVVariant serialization.
  • Extended atomic file replacement to preserve raw binary bytes.
  • Added structural tests that consume every byte, validate header/order/units/enums, verify selected-path export, and confirm atomic binary persistence.

Known limitations and next work

  1. Golden v4.4 acceptance: run the exact rebuilt Versioned Write.vi with controlled values, check the artifact into tests, and byte-compare this encoder. The schema is strongly established; runtime byte identity is not independently demonstrated yet.
  2. Compatibility planner: add a separate planner rather than changing the current handle-based behavior in place. Implement quintic C² construction, signed curvature, vertex-blend clothoids, extra arcs, and overlap handling.
  3. Time profiling: add 24-point quadrature, distance-to-parameter inversion, jerk-limited translation, and separately constrained holonomic rotation. Add jerk to any project model that does not currently persist it.
  4. Fixture matrix: straight and 90° Béziers; signed 30°/90°/120° clothoids; consecutive overlap cases; nonzero endpoint velocities; ±180° holonomic wrap; at least two sample periods.
  5. Commands later: when sequencing enters scope, reverse/golden-test LVVariant, LabVIEW Path, icon image, and subsystem-color flattening before allowing a nonempty command array.
