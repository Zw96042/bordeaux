Heading transition controls

Projectbordeaux
Versionv3
Statusdone · 2026-08-06

Make every heading-law boundary explicit: the user chooses where the transition occurs, whether heading or translation keeps its schedule, and how much path length is available for the blend.

Context

Today, switching heading laws always applies a minimum-jerk correction over the first 0.75 m of the new segment. Angular limits then reduce translational velocity so the corrected heading remains positionally exact. This is safe, but hidden and unnecessarily slow when two laws are already close.

The existing constraint-range timing priority remains useful for arbitrary stretches. This plan adds a boundary-specific policy so a heading-law change does not require creating a separate range.

Recommendation

Store an optional headingTransition object on the waypoint that starts the new outgoing segment. Omission preserves today’s behavior: transition after the boundary, heading timing priority, 0.75 m blend.

Implementation steps

  1. Add the typed boundary policy, validation, project round-trip support, and reversal remapping.
  2. Generalize heading smoothing in the shared planner, LabVIEW compatibility planner, and browser preview to blend before, after, or across both sides.
  3. Merge transition timing priority with constraint-range priority. Heading wins on any overlap unless every active policy selects translation.
  4. Add compact controls to the segment inspector only when the selected segment begins with a heading-law change.
  5. Add regression coverage for defaults, each placement, translation priority, validation, reversal, and browser/shared parity.

Risks & mitigations

Decisions

  • The policy belongs to the boundary waypoint, not the path or a constraint range.
  • Split divides the authored blend distance equally across the two adjacent segments.
  • Changing heading mode does not silently rewrite the boundary policy.
  • LabVIEW .bdx receives flattened samples but cannot reconstruct this editor-only metadata.
