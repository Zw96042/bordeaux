Make the live editor use the selected LabVIEW geometry, restore Bordeaux’s speed-dependent motor limit, and reduce interface noise without changing the proven v4.4 binary contract.

Context

The planner selector previously changed export metadata but the canvas always ran the original per-segment cubic/G1 sampler. This made LabVIEW Bezier and clothoid look and profile identically. The right inspector also exposed legacy binary details as ordinary path controls, while the field overlay repeated a large compatibility disclaimer.

The compatibility boundary remains additive: profiledSpline and optimizedTrajectory retain their behavior, imported v4.4 StoopidFast values round-trip losslessly, and the browser preview remains explicitly approximate because it cannot import the compiled TypeScript planner.

Recommendation

Route plannerId through every renderer derivation, mirror the shared degree-five Bezier and vertex-blend clothoid geometry in the static renderer, and use the same DC-motor torque-speed envelope in browser and export timing. Keep StoopidFast in the compatibility model only, and move optional rotation/binary controls behind disclosures.

Motor invariant. While speeding up, available acceleration is activeMaxAccel × clamp(1 − |v| / robot.maxSpeed, 0, 1). The active constraint range is chosen before scaling. Deceleration remains independently limited.

Implementation steps

  1. Pass plannerId into the active path, path manager, and autonomous preview derivations.
  2. Add renderer copies of the quintic shared-derivative Bezier and trimmed vertex-blend clothoid formulas, including 0.02 m densification for stable timing.
  3. Apply the linear torque-speed envelope to both shared LabVIEW planners and the compatibility preview; leave existing planners untouched.
  4. Hide irrelevant handles in clothoid and automatic-tangent modes, remove the StoopidFast input, and preserve its imported/exported value.
  5. Collapse empty outline sections, compact the path summary, progressively disclose rotation and .bdx flags, and replace the large compatibility card with a quiet approximation label.
  6. Give the telemetry graph scale headroom, current and peak readings, time labels, a curve-position marker, and keyboard seeking.
  7. Track pointer-focused buttons so Space starts playback without leaving a white ring while Tab-focused buttons retain native keyboard activation.

Risks & mitigations

Verification

  • npm test: 76 tests, including distinct Bezier/clothoid renderer geometry, duplicate-waypoint resilience, and motor-envelope checks for both planners.
  • npm run typecheck, npm run build, and Electron smoke.
  • Live Electron review: selector changes duration/limits, StoopidFast is absent, compact LabVIEW controls are present, the graph exposes time/current/peak data, and clicking its button then pressing Space starts playback without retained focus.

Open questions

  • Bit-identical timing remains impossible to claim without controlled curved LabVIEW fixtures; the public branch also contains known broken quotient/remainder limiter wiring.
  • When a future renderer build pipeline can bundle shared TypeScript directly, remove the duplicated browser geometry and then reconsider the approximation label.
