Original audit — September 5, 2026

Do not sign off the current UI for production yet. The principal problem is inconsistent interaction and state contracts across screens, reinforced by incomplete visual verification.

This review covers the current dirty working tree based on e2e3ea01ee097792e8aeda8aabf769b97057f493 on main, September 5, 2026. It is not a review of that commit alone. App behavior was not changed during this audit; the deliverables are this review, linked findings, and a repository UI review procedure.

Fix before release

1. Selection gesture deletes a waypoint

High · Rendered reproduction + source
src/renderer/components/Panels.jsx:146

Shift-clicking the first waypoint changed the count from 3 to 2. The same modifier means range selection in the library, whose on-screen hint is directly above the outline. Undo exists, but an ordinary selection gesture should not silently edit geometry.

Correction: Remove Shift-click deletion. Keep deletion in explicit Delete controls and the documented keyboard action. Test modifier clicks without geometry mutation.

2. Coordinate displays ignore Imperial units

High · Rendered reproduction + source
src/renderer/components/RobotPage.jsx:252; src/renderer/components/Panels.jsx:150

With Imperial selected, custom footprint inputs still display raw -0.42 coordinates with no unit, and the waypoint outline still displays 10.8, 5.9 meters while the inspector converts values. Custom vertex edits also commit the raw number as meters. This is a potentially consequential dimensional error, not just inconsistent copy.

Correction: Use UnitPrefs consistently for display and entry, expose units, and verify round-trip editing does not change canonical coordinates.

3. Optimizer turns planning failure into indefinite loading

Medium · Source state analysis
src/renderer/app/App.jsx:702; src/renderer/app/App.jsx:1794; src/renderer/components/OptimizationPanel.jsx:37

normalReady is false for errors, but the panel receives pending: !normalReady. A failed baseline can therefore show Preparing path and disable the action without reaching a useful error state. The field may report the error separately, but the panel still misstates its state.

Correction: Pass loading and error separately. Show one actionable failure, retain a way to edit or retry, and test a rejected baseline worker.

4. Routine drag feedback offers unsupported cross-branch moves

Medium · Source event/model analysis
src/renderer/components/RoutinePanel.jsx:26; src/renderer/lib/routineModel.js:315

Drag hit testing accepts any routine step, while reorderRelative permits only the same sibling array and silently ignores other targets. The insertion feedback can promise a move that dropping never performs.

Correction: Restrict valid targets to the model-supported siblings, or explicitly implement cross-branch moves. Test both valid and invalid targets using real pointer input.

5. Field context menu has no focus handoff

Medium · Source interaction analysis
src/renderer/components/ui.jsx:336; src/renderer/components/EditorLibrary.jsx:70

The field context menu positions buttons and closes on Escape/outside click, but does not focus its first action, implement arrow navigation, or restore focus. The library menu already implements these behaviors. Opening the field menu does not establish a usable keyboard interaction context.

Correction: Converge on one menu interaction contract, with focus entry, arrow navigation, Escape, and focus return. Verify Shift+F10/context-key access as well as pointer opening.

6. Pairing and failure screens need stable state presentation

Medium · Source state analysis
src/renderer/components/RobotPushDialog.jsx:29; src/renderer/components/RobotPushDialog.jsx:36; src/renderer/components/RobotPushDialog.jsx:88; src/renderer/components/RobotPushDialog.jsx:96

During pairing the identity review disappears and the endpoint form returns with disabled Connect. On failure, the same c.error can appear in two alert regions. Delayed operations therefore change the screen unexpectedly, and failures can be announced twice.

Correction: Retain identity information while pairing with a pending action. Render one authoritative error with recovery controls. Test a deferred pairing promise and a rejected push.

7. Push controls reference undefined font tokens

Medium · Source CSS analysis + rendered review
src/renderer/styles/robot-push.css:139; src/renderer/styles/robot-push.css:173; src/renderer/styles/robot-push.css:195

The stylesheet uses --font-mono and --font-ui, but the app defines --mono and --ui. Invalid font shorthands lose their intended size, weight, and family. The push review also visibly retains a different typography treatment from the editor.

Correction: Use defined shared tokens and verify computed fonts/sizes in endpoint, review, and outcome states.

8. UI verification is stale and is not a CI release gate

High · Executed checks + CI source
scripts/verify-optimizer-ui-electron.cjs:148; scripts/verify-optimizer-ui-electron.cjs:100; .github/workflows/ci.yml:35

The original optimizer harness fails waiting for keyboard reorder focus. Its later assertions also target the removed Display units control and export button, and contain outdated stale-trajectory expectations. The later remediation confirmed that opening the optimizer intentionally starts a quick search. At audit time, CI runs desktop smoke but not these full UI harnesses. A green build can miss the screens under discussion.

Correction: Diagnose reorder focus separately from stale expectations, update the harness to the current product contract, then run maintained UI flows under CI with captured artifacts and a rendered review. Do not silence failing expectations indiscriminately.

Consistency work

Primary names still truncate outside segment rows

Rendered at 1100×720: a waypoint with heading and stop badges becomes Waypoin…; routine titles and metadata use nowrap/ellipsis and in-flow hover actions. The segment-only fix did not establish a shared readable row pattern.

src/renderer/styles/library.css:78; src/renderer/components/Panels.jsx:148; src/renderer/styles/app.css:652

Extend the readable row treatment to waypoints and routine nodes. Prioritize names, put optional metadata underneath, reserve actions, and verify long data with the inspector open. Continue issue #169.

Visual conventions remain different across workspaces

Settings, routine metric cards, optimizer PREVIEW, and push details retain uppercase headings; diagnostics uses a different surface and a long introductory disclaimer. This is a consistency/taste assessment rather than a demonstrated accessibility failure.

src/renderer/styles/app.css:554; src/renderer/styles/app.css:1009; src/renderer/styles/robot-push.css:161; src/renderer/components/DiagnosticBundleDialog.jsx

Apply one compact type/spacing/surface vocabulary, preserving useful technical detail behind explicit disclosure. Start with labels and repeated containers, not a whole-app rewrite.

Routine counts lack scope

In the rendered branch fixture the library says 5 steps while playback says 4 steps: authored nodes versus the selected preview route. Both counts may be correct, but neither label explains the difference.

src/renderer/components/EditorLibrary.jsx:193; src/renderer/components/RoutineInspector.jsx:158

Label the playback count as the preview route or omit the redundant total; ensure the routine outline and inspector use the same named concept.

What is working

The shared library stays anchored when switching modes; routine flow occupies the main workspace; push review makes selected scope and preserved paths visible; normal trajectory fallback no longer requires an optimizer detour; and segment names now wrap. Preserve these behaviors. The healthy optimizer result shows a clear gain and a separate Apply action—do not replace that with automatic candidate application.

Preventing recurrence

docs/agents/ui-review.md now defines the expected interaction and visual conventions, representative data/states, actual pointer/keyboard checks, final screenshot inspection and independent review. AGENTS.md points UI work to that procedure. It is a review requirement, not a claim that CI now enforces it.

  1. Fix unintended deletion, inconsistent units, false loading states and misleading drag feedback first.
  2. Unify existing row, menu, dialog and field behavior; use shared, defined typography tokens. Avoid another layer of one-screen CSS exceptions.
  3. Repair the optimizer harness, wire maintained UI flows into CI, and retain screen artifacts for review.
  4. Before release, review every major workflow with long content, empty/loading/error/disabled states, both units, and minimum/default window sizes. A later UI change invalidates the affected portion of sign-off.
